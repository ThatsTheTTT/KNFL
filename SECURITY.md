# Security Policy

## Supported Versions

Only the latest commit on the `main` branch receives active security updates and patch releases.

| Version | Supported          |
| ------- | ------------------ |
| Main    | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

We take the security and integrity of KNLF seriously—especially regarding buffer overflows, memory leaks, and malicious stream parsing.

If you discover a security vulnerability, **please do not open a public Issue.**

### Reporting Process
1. Report the vulnerability privately by opening a **[Draft Security Advisory](../../security/advisories/new)** on GitHub or by contacting the repository maintainer directly.
2. Provide detailed information about the vulnerability, including:
   * Description of the bug/exploit.
   * A Proof of Concept (PoC) file or code snippet.
   * Potential impact on decoding/encoding systems.

### What to Expect
* **Acknowledgment:** You will receive a response acknowledging your report within 48 hours.
* **Assessment:** The maintainer will evaluate the issue and work on a fix.
* **Resolution:** A patch will be committed to `main`, and appropriate credit will be given (unless anonymity is requested).
